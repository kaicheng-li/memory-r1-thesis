## 3. 首轮分析中的关键理论问题

### 3.1 非零终端势会改变任务目标

设一次动作步为 t，势为 Φ_t；T 是动作数，γ 与 return 使用相同折扣。则

\[
\sum_{k=t}^{T-1}\gamma^{k-t}(\gamma\Phi_{k+1}-\Phi_k)
=-\Phi_t+\gamma^{T-t}\Phi_T.
\]

因此默认 γ=1、初始空 bank 时，整条轨迹目标等价于

\[
R_{QA}+\eta\Phi_T-\lambda N_{invalid}.
\]

这包含额外的终端覆盖偏好。反例：策略 A 的期望 QA 奖励为0.8、终端势0；策略 B 为0.6、终端势1；η=0.5时，目标分别是0.8和1.1，排序反转。即使原奖励是二值 EM，策略期望也可取这些值。

首轮同时写“等效终端证据奖励”和“不破坏策略排序”，逻辑矛盾。Ng 等的 PBRS 结论有 MDP、折扣及终止边界条件，不能绕过这一点。[1][2]

**本次纠正上轮修改：**上轮直接把最后势置零会改变用户原本的辅助目标，不是纯工程修复。现在显式提供 `--terminal-potential observed|zero`，默认 `observed` 保持原分支目标；`zero` 作为有明确含义的实验变体。`run_MemR1.sh` 用 `TERMINAL_POTENTIAL` 传递配置，run manifest 记录该选择。

### 3.2 “逐轮 reward”不等于“新增局部信用信息”

若终端势为零，完整 return-to-go 的塑形贡献就是 `-ηΦ_t`。同一状态的候选共享 Φ_t 时，它在组内减均值与标准差中完全抵消。第0步从相同空 bank 开始尤其如此。只把末端奖励写成差分，在这类 estimator 下不能自动获得新的局部学习信号。

在当前按轮位分组的实现中，后续 memory state 不同，Φ_t 也不同，因此优势确实可能改变；但这种改变掺入了状态差异，不能直接认定为动作信用更准确。更细地说，状态相关 baseline 在理想 on-policy REINFORCE 下可以不改变期望梯度；问题是这里还有有限组归一化、跨状态比较、token 平均、clipping 与零方差筛选，不能把该理想结论当成当前优化器的等价性证明。

默认非零末端势下，差分的 RTG 包含“终端覆盖奖励 − 当前势”。必须增加 **terminal-coverage-only 与差分 RTG** 的消融，才能区分收益来自辅助目标还是奖励分布/优势估计。只做 η=0/0.5 可以检验组合方法，但不能单独证明 credit assignment 改善。[1][3][4]

### 3.3 共享初始快照没有使后续状态相同

共享 snapshot 能控制初始状态，缩短 K 能减少成本。但第一个动作不同后，M_1 即不同；第二轮及以后仍不能称“同状态采样”。GiGPO 的状态分组不能仅凭“都有锚点”视为等价。[5]

要研究真正的同状态局部反事实，需要对每个明确状态采样动作、续跑或估计 Q，或构建有严格状态匹配依据的分组；这增加了算法和算力工作。大纲已限定不实现 local rerollout，因此不应把这一整套方法悄悄加进主线。

快照也不保证28题全部“有效回收”：快照必须位于窗口起点之前，包含所需的早期语义事实、保留可审计来源且不含未来轮次。单步 target-turn 的 `old_bank` 不能直接拿来当更早 K 窗口的初态，否则可能注入窗口内未来信息。teacher 抽取漏证据时，题目被加入文件也不等于可答。

### 3.4 当前 provenance 不是语义证据

代码位置：[runtime](C:/project/mythesis/memory_r1_reproduction/memfactory/memory_runtime.py:71)、[potential](C:/project/mythesis/memory_r1_reproduction/scripts/train_manager_grpo.py:142)。

- ADD 不论写了什么文本都盖当前 dia_id。若题目证据就是此轮，写“unrelated garbage”也可取得 coverage=1；新增测试明确复现这一现象。
- UPDATE 保留旧来源但不添加当前来源。毁掉旧事实仍可能保留奖励；真正合并新证据又可能得不到奖励。这是双向偏差，并可能诱导 ADD 多于 UPDATE。
- 检索覆盖同样看被检索条目的来源。top-k 较大或 bank 较小时，垃圾文本仍可能被检索，不能构成可靠防作弊机制。
- top-k 限制 Answer 可见条数，不限制整个 bank 的规模；没有容量/长度代价就不能声称防止囤积。
- 原大纲“UPDATE 合并关键证据立即获正奖励”的例子，当前来源语义并不保证实现。

现阶段可称 **turn-origin coverage proxy**。若坚持“语义证据保留”贡献，需另做：按 fact/span 标识证据；对新 memory 文本与原证据做支持关系检查；UPDATE 重新验证旧与新支持集合；在人工标注子集报告误判率、ADD/UPDATE 分层结果。训练期标签不进入 Manager/Answer 输入。这可以借鉴 supporting-fact supervision / privileged information，但这些文献不证明当前 ID 规则正确。[6][7]

本次仅修复了 provenance 不应出现在策略输入的问题，没有伪造一个未经验证的语义 evaluator。后者是研究设计与标注工作，不能通过字符串相似度替代后就宣称完成。

### 3.5 势函数、时间和目标还需明确

当前实现为

\[
\Phi_t(q)=\tfrac12\frac{|E_q\cap Seen_t\cap Sources(M_t)|}{|E_q|}
+\tfrac12\frac{|E_q\cap Seen_t\cap Sources(Retrieve(q,M_t))|}{|E_q|}.
\]

它与大纲的“仅已出现证据作分母”不同。两者均可定义为势，但并非单调：DELETE、文本更新后的排名变化、已出现证据分母增大，都能使覆盖下降。“单调”不是合法势函数的必要条件。

时间相关与 question-conditioned Φ 应把时间/问题集纳入训练 MDP 的扩展状态，验证相邻状态使用同一任务势与折扣。只引用 Dynamic PBRS 不足以保证任意任务切换都策略不变。[8]

代码跳过空 facts 轮次，γ 现在按**有效动作步**折扣，非原始 dialogue turn。γ=1时无折扣时间差异；γ<1须明确这一任务定义。`--algorithm ppo` 没有 critic/GAE，是 sequence-ratio + group advantage 变体，不能称标准 PPO 实现。Manager 每组仅一次更新时，首次前向 old/new ratio 通常接近1，clipping 没有多轮 PPO 的保护效果，但这本身不代表梯度为零。[3][4]

## 6. 建议实验 pipeline 与通过条件

1. **锁定协议与数据。** 选定 reward=EM 或明确版本的 F1；固定 tokenizer、chat、检索、top-k、cached facts 与 Answer checkpoint。保存数据/代码/模型指纹。长短数据分别命名，不能让R1用150题、R3用122题。
2. **检验 reward oracle。** 在 train 做 empty-bank、当前 frozen Manager bank、合法 ADD-all-facts bank、gold-support bank 的配对评答；gold-support 只用于训练期诊断，不进入部署策略。报告正负变化与净ΔF1/EM，同时抽样检查抽取和检索。不能把 ≥15 个 matcher 翻转当充分条件。
3. **一次真实 QLoRA smoke test。** G=2、少量有/无长程QA，记录峰值显存、每动作秒数、生成截断率、valid率、组回报方差、梯度范数、adapter是否变化与 reload 后输出。短输出预算会使JSON截断，128/256不能凭省显存直接设成默认。
4. **固定 Answer。** base Answer若有区分力可直接冻结；否则一次性训练/验证选好 Answer，再将同一权重用于所有 Manager 因果对照。Answer训练仍是EM，Manager可选F1，这种差异要记录，不等于错误。
5. **先训 R1，再训 R3。** 相同 seeds、数据顺序、训练预算、非法惩罚、KL和选模规则。零方差筛选会使实际有效更新数不同，报告 attempted与effective updates、tokens和wall time，不只报epoch。
6. **每epoch完整validation选模。** 当前已接入，指标与策略固定。test仅在协议确定后评测，不能用test选η、K或checkpoint。保留full-dialogue主指标与target-prefix诊断的区别。
7. **测试与机制分析。** 完整8对话1307 QA，类别、跨度分层；记录 memory数量/token预算、语义支持抽查、来源覆盖与QA关系、动作分布。QA同对话相关，采用对话聚类的配对bootstrap并报告每对话差异；只有8个test对话时区间仍不稳，不能把1307题当独立样本。

建议矩阵（各训练条件至少3 seeds；先 pilot 再扩展）：

| 条件 | 定义 | 可回答的问题 |
|---|---|---|
| R0a | 未训练Manager + base Answer + 固定facts | 原始系统参考性能；不称数学下界 |
| R0b | 未训练Manager + 与R1/R3相同的冻结Answer | 区分Answer本身带来的变化 |
| R1 | 序贯同trainer，η=0 | 主要因果对照；仍含共同的非法惩罚与KL |
| R2 | baseline-lora单步版本 | 单步方案参考；检索、数据、训练语义差异逐项声明 |
| R3 | 与R1完全相同，η=0.5，observed terminal | 证据来源辅助目标的组合效果 |
| R3-T | 仅终端覆盖奖励，其他同R3 | 区分辅助目标与差分/优势估计效应；尚未实现此模式 |
| R3-Z | zero terminal | 边界与估计器诊断，不能预设能改善训练 |

资源不足时优先R0b/R1/R3与必要机制诊断，不能靠堆多组弱对照满足论文复杂度。η=0.5只是预设候选，非文献保证；语义校验势、检索替换、快照K实验应分别改变一个主要因素。

**硕士论文质量的可控部分**是问题定义、可重复pipeline、有效对照、误差分析、可解释结论；无法保证正收益。若R3只提高来源覆盖却不提高QA，或奖励无意义ADD，应诚实视为代理目标失效的证据，再做有针对性的语义支持改进。这比宣称“密集奖励理论成立所以应该涨点”更有学术价值。

## 7. 仍未完成、正式实验前需要补齐的部分

1. **来源代理的语义有效性。** 当前仍有可复现的奖励漏洞，尚无事实支持标注/校验器。
2. **序贯反事实预检与丰富训练日志。** 当前已具备验证选模，尚无完整precheck gate、逐组QA/coverage/KL/有效更新率的持久日志。
3. **真实硬件可行性。** 本机为CPU torch，缺少peft/bitsandbytes等实际QLoRA运行依赖；未执行训练、未生成新的Answer或Manager权重，未测实际显存/吞吐。
4. **标准化正式评测。** multiset F1是清晰的本地指标，尚未与指定LoCoMo官方实现逐项对齐。自定义matching/LLM judge仅作辅助；不能替换主指标而不声明。
5. **训练状态恢复与更完整版本锁定。** 当前保存adapter，未保存optimizer/RNG/采样进度用于精确resume；manifest尚非全部文件内容快照。
6. **长程主张与预算。** 完整前缀数据已生成，但未训练验证；短窗口pilot不能替代长期记忆实验。

本轮没有修改成MiniLM、没有把共享快照当成已经解决理论问题，也没有仅凭review就冻结baseline并宣布其唯一可训。

## 8. 文献与它们实际支持的范围

以下链接用于定位原文；本轮未在线重新核验版本/页码，不把其他模型的引文归因当成已证实事实。Memory-R1/Memory-R2 的逐行算法对应与实现版本仍需锁定原文/commit。

1. Ng, Harada & Russell (1999), *Policy invariance under reward transformations: Theory and application to reward shaping*. [原文PDF](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)。支持特定势差与边界下的策略不变性，不支持任意非零终端势。
2. Grześ (2017), *Reward Shaping in Episodic Reinforcement Learning*. [AAMAS论文](https://www.ifaamas.org/Proceedings/aamas2017/pdfs/p565.pdf)。有限episode的终止处理需要认真定义。
3. Shao et al. (2024), *DeepSeekMath*. [arXiv:2402.03300](https://arxiv.org/abs/2402.03300)。GRPO基准目标；不是跨不同memory state的任意组归一化保证。
4. Schulman et al. (2017), *Proximal Policy Optimization Algorithms*. [arXiv:1707.06347](https://arxiv.org/abs/1707.06347)。用于说明clipped surrogate与当前sequence-ratio变体的差别。
5. *Group-in-Group Policy Optimization for LLM Agent Training* (GiGPO, 2025). [arXiv:2505.10978](https://arxiv.org/abs/2505.10978)。应比较其状态分组定义，不能把共享初始snapshot直接称为同一方法。
6. Yang et al. (2018), *HotpotQA*. [arXiv:1809.09600](https://arxiv.org/abs/1809.09600)。支持将supporting facts作为独立监督对象；不证明来源ID等于语义支持。
7. Pinto et al., *Asymmetric Actor Critic for Image-Based Robot Learning*. [arXiv:1710.06542](https://arxiv.org/abs/1710.06542)。训练评估侧额外信息的范式参考，不是本方法正确性证明。
8. Devlin & Kudenko (2012), *Dynamic Potential-Based Reward Shaping*. [AAMAS论文](https://www.ifaamas.org/Proceedings/aamas2012/papers/1C_3.pdf)。时间相关势的构造有条件；引用本身不能修复边界或跨任务不一致。
9. Maharana et al. (2024), *Evaluating Very Long-Term Conversational Memory of LLM Agents* (LoCoMo). [arXiv:2402.17753](https://arxiv.org/abs/2402.17753)。基准与任务背景，不为本地split赋予官方地位。
10. *Memory-R1* (2025). [arXiv:2508.19828](https://arxiv.org/abs/2508.19828)。母体方法；当前QLoRA、数据上下文及优势估计修改需单列，不称严格复现。
11. Hu et al., *LoRA*. [arXiv:2106.09685](https://arxiv.org/abs/2106.09685)；Dettmers et al., *QLoRA*. [arXiv:2305.14314](https://arxiv.org/abs/2305.14314)。支持参数高效适配与量化基座方案，不能保证三模型并驻及长序列反传在指定GPU可行。
12. Wiewiora (2003), *Potential-Based Shaping and Q-Value Initialization are Equivalent*. JAIR 19:205–208（期刊条目链接本轮未核验）。等价性有具体学习设定，不能直接推为LLM GRPO收益保证。
