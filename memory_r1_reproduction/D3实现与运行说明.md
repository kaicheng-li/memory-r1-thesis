# D3′ 实现与运行说明

本文件记录当前代码协议，取代早期草案中未落地的 λ 奖励加项。baseline-lora 分支不改动，R2 仍为必做基准；本分支统一了 MiniLM 检索、baseline F1、答案解析和主验证指标，但不宣称两个 trainer 的全部工程细节相同。

## 已接通的路径

`causal cached-facts tuples → frozen Answer teacher/noop controls → train-only eligibility → G Manager rollouts → retrieved-memory Answer → rewards/returns → GRPO or noop advantages → optimizer → group log/checkpoint → full-dialogue validation`。

- `s_T`：同一冻结 Answer 读取该训练前缀中的 teacher facts 全集。不向它提供 gold answer 或 evidence 标签。
- `s_0`：同一 Answer 读取空 bank。本实现每条轨迹从空 bank 起步，拒绝非空 `initial_bank`；不使用目标轮 `old_bank` 回填过去。
- `s_i`：同一 Answer 读取候选 bank 检索结果。
- `--control-gate threshold --control-threshold τ`：仅训练时用 `s_T ≥ τ` 选题。阈值无默认值，需用 train 预检确定。低分仅是该控制条件失败，不证明 Answer 不会做题。上下文错误另记，不作为零分。
- `--control-gate off`：明确关闭分数门控，仍在 noop 模式计算控制诊断；控制输入发生工程错误的题不作为有效对照。
- QA 平均、Φ 平均和 noop 平均使用完全相同的通过门控题目；不单独对不同候选筛题。验证/测试不消费 evidence、不使用训练门控。

奖励在非法动作位置扣罚；终端加平均 QA 分数。dense 模式每步加 `η(γΦ_next−Φ_previous)`；terminal 模式仅末步加 `ηΦ_final`，要求 γ=1、observed 终端边界，确保与 dense 的总覆盖奖励一致。Φ 仍是轮来源覆盖代理，不能证明文本语义正确。

noop 优势为 `clip((return_to_go−s_0)/adv_scale, ±adv_clip)`，默认 scale=1、clip=5，并要求 γ=1。只有某动作位置所有残差绝对值均不超过 epsilon 才跳过；全等但低于 noop 的候选仍更新。GRPO 选项保留组均值/std 和零方差跳过，用于 estimator 对照。两者都使用 per-token clipped surrogate；这不意味着裁剪后的训练梯度满足无偏保证。

## 上下文与诊断

teacher/noop/candidate/完整对话验证及最终评测都使用同一 `safe_answer`。先计算包含 chat template 的实际 token 数，同时预留生成额度。超预算输入按说话人分块、用同一冻结 Answer 做问题条件化信息抽取，再汇总回答；单条长 fact 也分片覆盖原文。每次调用的输入/输出 token 数、预算、压缩层级写入结果。

这解决静默截断，不保证语义无损，也不是更强 teacher 模型。压缩可能漏信息，teacher facts 也可能不完备；`compressed` 分数要与 `direct` 分开检查。生成撞到输出上限或无法在限定层数内压缩时显式报错。控制端记录 context_error；候选端记录 aborted_group 后停止，不把基础设施失败罚给 Manager。

分块后推理次数取决于文本长度，所以不再宣称固定 +25% 开销。完整控制每题至少增加 teacher/noop 两次回答，组内 G 条候选共享。日志中的 calls 才是实际成本依据。

## CPU 检查

从仓库根目录运行：

```powershell
python -m unittest discover -s memory_r1_reproduction/tests -v
python -m compileall -q memory_r1_reproduction/memfactory memory_r1_reproduction/scripts memory_r1_reproduction/evaluation memory_r1_reproduction/tests
```

恢复集成测试用小型 CPU 可训练模型执行真 backward/AdamW：连续跑两组，对照第一组保存后模拟中断再恢复第二组，检查模型权重、optimizer 和 Python/NumPy/Torch RNG 完全一致。另测 noop 三个数值例子、门控同时屏蔽 QA/Φ、控制组复用、原文分片全部送达、预算失败、预检/训练口径、MiniLM 排名（注入假向量）及最终评测入口。CPU 测试不验证真实 MiniLM 下载、QLoRA CUDA 内核或真实模型回答质量。

## GPU 操作顺序

先在 GPU 环境安装 `requirements/memfactory.txt` 对应依赖。MiniLM 默认模型 `sentence-transformers/all-MiniLM-L6-v2`，可用 `MEMORY_EMBEDDING_MODEL` 指定本地副本。`MEMORY_RETRIEVAL_BACKEND=lexical` 仅用于明确的独立消融；不存在静默回退。训练清单记录 backend/model/device 和包版本。

以下命令从 `memory_r1_reproduction` 执行，路径需替换为 GPU 机实际路径：

```bash
export DATA_PATH=./data/review/manager_tuples_train_fullprefix.jsonl
export MODEL_PATH=/your/base/model
export ANSWER_ADAPTER_PATH=/your/shared/frozen/answer/adapter
python scripts/precheck_sequential.py \
  --data-path "$DATA_PATH" --manager-model "$MODEL_PATH" \
  --answer-model "$MODEL_PATH" --answer-adapter "$ANSWER_ADAPTER_PATH" \
  --output-dir output/precheck_smoke --limit-tuples 2
```

预检默认四条件：empty/noop（空起点时同一条件）、frozen Manager、teacher all facts、gold-support facts。gold-support 仅离线诊断，与 raw prefix 不等价；可加 `--include-raw`。删去 `--limit-tuples` 并换输出目录跑完整 train 预检，查看 `paired.jsonl` 和 `summary.json` 的分数、错误、压缩情况及 threshold sweep 后，固定阈值。脚本只展示阈值候选保留数量，不自动宣布哪个阈值有科学依据。

```bash
# 下列值由上述预检确定，不要把示例当作已验证阈值。
export CONTROL_THRESHOLD=<your_calibrated_value>
export OUTPUT_DIR=output/r3_noop
export NUM_GENS=2
export CHECKPOINT_EVERY=1
bash scripts/run_MemR1.sh
```

脚本默认要求显式的共享 Answer adapter，避免每个消融各训一个 Answer。仅需要首次 bootstrap 时显式设 `BOOTSTRAP_ANSWER=1`；bootstrap 后必须固定同一个 adapter 再跑比较。CLI 允许省略 adapter 使用冻结 base Answer，但不能与不同 Answer 条件混比。Manager 有共享起始 adapter 时，预检传 `--manager-adapter`，训练脚本设置 `MANAGER_ADAPTER_PATH`，KL reference 也使用这个初始 adapter。

## 实验矩阵

| Run | estimator | evidence weight | shaping mode |
|---|---|---:|---|
| R1-GRPO | grpo | 0 | dense |
| R1-D3′ | noop | 0 | dense |
| R3-D3′ | noop | 0.5 | dense |
| R3-T-D3′ | noop | 0.5 | terminal |
| R2 | baseline-lora 原 trainer | 按基准协议 | 单步基准 |

脚本变量为 `ADVANTAGE_ESTIMATOR`、`EVIDENCE_WEIGHT`、`SHAPING_MODE`。同 trainer 对照固定 Answer/初始 Manager、gate/threshold、数据、检索、生成设置、种子、预算及验证协议；跑多个种子，报告样本数和成本。R2 与序贯方法是整体系统对比，不能将其差异全部归因于塑形。以上权重不是已经验证最优的超参数。

## 日志、恢复、选模

不传 `--group-log` 自动写 `output-dir/groups.jsonl`；包含控制答案/分数/状态、有效题数、noop、候选答案、每步 Φ/shaping/reward、return、advantage、跳过原因、有效动作数和 loss。

每 `--checkpoint-every N` 个完成的 tuple 写一个 checkpoint，epoch 末也保存。包含 adapter、optimizer、所有 RNG、epoch、下一 tuple 游标、best checkpoint 记录，以及数据/adapter 哈希和训练配置合同。只有完整目录才被 `latest_checkpoint.json` 指向。

```bash
export RESUME=/your/run/epoch_0_tuple_50
export OUTPUT_DIR=/your/run
bash scripts/run_MemR1.sh
```

或直接传 trainer `--resume <checkpoint-dir>`。按最新 checkpoint 恢复，重算尚未保存的组；恢复到较早历史位置建议另开输出目录，代码拒绝覆写已有完整 checkpoint。训练数据、模型/adapter、检索、奖励等配置不符会报错；可更换日志/输出路径或增加总 epochs。仅加载自己可信的 checkpoint（含 Python/NumPy RNG 对象）。日志用 resume 事件说明回退边界；分析时按 `(epoch,tuple_index)` 保留恢复后结果，不将重算组重复计入。

选模明确用 `reward_f1_unique_overlap`（baseline 相同的 unique-token overlap / 原 token 数分母定义）；同时保留 `token_f1_multiset`。重复词时两者可能不同。最终入口 `evaluation/evaluate_test_final.py` 已使用共享 roll-forward，汇总两种 F1、EM、BLEU1；不应用训练 gate。其本地 split 不能仅凭代码宣称与论文官方结果等价。

## 学理边界与参考

- Williams (1992), REINFORCE：[论文 DOI](https://doi.org/10.1007/BF00992696)。动作无关 baseline 在未裁剪 score-function estimator 中不改变梯度期望；这里的窗口起点 noop 是轨迹级控制，不是每步局部反事实重跑。
- Greensmith, Bartlett & Baxter (2004), Variance Reduction Techniques for Gradient Estimates in Reinforcement Learning：[JMLR](https://www.jmlr.org/papers/v5/greensmith04a.html)。支持 baseline/方差分析，不保证 noop 比组均值更优。
- Ng, Harada & Russell (1999), Policy Invariance Under Reward Transformations：[论文](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)。边界条件必须满足才有策略不变性；非零 observed 终端势在这里引入辅助覆盖目标，不宣称保持原 QA 排序。
- Foerster et al. (2018), Counterfactual Multi-Agent Policy Gradients：[论文](https://arxiv.org/abs/1705.08926)。作为反事实基线背景；本实现不计算 COMA 对动作分布的边际化，不能称为其精确特例。
- Reimers & Gurevych (2019), Sentence-BERT：[论文](https://arxiv.org/abs/1908.10084)。句向量检索背景；使用 MiniLM 是与基准保持检索器一致的工程选择，不是本文额外算法贡献。

控制门控改变了训练样本分布，无法由上述 baseline 定理证明无偏；它应被报告为训练条件选择，并用关闭门控诊断/消融及全量评测检查影响。以上均为理论依据和可验证假设，不是实验质量保证。GPU 冒烟、阈值校准和多种子真实实验仍须实际运行。
